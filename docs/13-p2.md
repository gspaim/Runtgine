## G-30 — Cancel / timeout / retry / concorrencia

**Status: CONFIRMED** (variante B)

| Tema | Corte |
|---|---|
| Timeout | Shell `timeout_ms`; Runner cancela step → `runtime.timeout` |
| Cancel | `CancelRun(run_id)` real no Core: context cancel + estado `cancelled` |
| Retry | **Retry automatico configuravel por step** (ex.: `max_retries`, backoff simples); alem do retry 1x de parse JSON do LLM (G-25) |
| Concorrencia | Multi-run + limite `max_concurrent_runs` na config (default sugerido: 4) |
| Step fail | Apos esgotar retries, falha do step falha o run (sem continue-on-error no v0) |

Defaults sugeridos de retry: `max_retries: 0` (off) no Shell; LLM/pipeline podem default > 0 via config/manifest — confirmar na implementacao sem surpresas.
